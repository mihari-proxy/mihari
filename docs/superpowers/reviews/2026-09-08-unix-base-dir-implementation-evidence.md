## Native execution and evidence contract

`scripts/test/unix-layout-security.sh --root <anchor> --uid-a <UID> --uid-b <UID> --report <results>/result.json` accepts only explicit ephemeral hosted root CI. Preparation verifies root-owned, non-writable, ACL-free ancestors under `/var/lib` or `/Library`, creates a unique 0711 anchor and separate 0755 results directory, and writes separate root0600 ownership markers containing matching run and native identities. Read-only UID/account/binary preflight precedes directory mutations. A third exclusively created root0600 `<anchor>.prepare.json` binds the exact run, trusted parent and recorded directory identities before later preparation actions. The workflow publishes deterministic recovery routing before this privileged step; routing alone grants no cleanup authority. Short creation/identity-sync sections defer TERM, and failed preparation preserves a sanitized failed result and recoverable ownership record. Replaced or unrecorded objects fail closed. Two previously unused accounts are created; Linux uses an existing verified primary group, Darwin uses GID20. Both actual UIDs/GIDs are verified. No runner account or fixed fixture UID is reused.

Unprivileged preparation compiles the reviewed native packages with Go1.26.5, CGO0 and `unix_security`, recording revision, OS/architecture, tag, executable hash/size and fixed Go/Python paths/hashes. Root stages verified bytes as searchable root0755 executables. The privileged phase executes fixed Go `tool test2json -t -p <exact package> <binary> -test.v=test2json -test.count=1 -test.timeout=...`; command status and parsed evidence are independent requirements. This replaces the R3 root `go test -json` compilation example to avoid privileged module/toolchain fetch and provide searchable, identity-checked UID helpers. Go1.26.5 test2json source preserves child failure status. Root uses an explicit environment, local toolchain, offline proxy/sumdb, fixture caches and fixture telemetry `off` configuration.

Account preparation and test phases use a gate-controlled supervisor: cleanup intent is synced before process creation, actual PID/start identity is synced before its child may execute, and the leader remains alive until its group is joined. TERM propagates to the owned group. If descendants refuse to exit, cleanup fails and retains accounts/anchor/ledger for the ephemeral VM boundary; it does not discard authority by letting the leader disappear. Linux executes in an actual private mount namespace; its real bind test syncs source/target identities and namespace before mount, enabling identity-checked unmount after interruption.

Raw events and cleanup records are copied/synced as root0600 files to the independent results root before cleanup. Cleanup verifies process identity, then mounts, accounts and anchor, and records every failure. An always-recovery attempt may finish cleanup but cannot erase the original failure. Only sanitized `result.json` is 0644/uploaded; successful upload precedes marker-checked results removal. Failed upload preserves the results directory. KILL/runner loss is bounded by disposable VM destruction, not claimed as catchable by traps.

## Accepted scope decisions and costs

| Decision | Preserved boundary / cost |
| --- | --- |
| System B/D versus UID-local U; ordinary users control the shared proxy | C is public to local users; private D and other users' U remain denied. This is machine management authority, not per-user proxy isolation. |
| Typed root policy and finite trusted core hashes | Unsupported YAML/provider/MRS/core versions fail closed; Windows and nonroot private configuration remain compatible. |
| Explicit capability anchors and retained permanent locks | Full root-chain checks and native mount/identity checks; no ancestor repair or lock-file unlink shortcut. |
| Installer stopped-business migration and fixed channel maintenance | These are narrow single-writer exceptions. TUI/CLI cannot directly modify arbitrary business state. |
| Installed startup reads activation before D and rechecks after data/E lease | It does not reacquire installation locks. Private system-service intent routes to B but grants no authority without actual root, matching P/E/C/I and executing binary hash. Unmarked private foreground remains P-only. |
| Root-P channel maintenance checks relevant incomplete B while holding only P | No B lock/create/write, no manager inspection; unrelated valid B may proceed; malformed B fails closed. Nonroot P does not read B. |
| Once-resolved custom I supplies `<I>/install-trust` | No source/request/adjacent checksum becomes root trust. An administrator must provision the trusted manifest for custom I. Standalone update retains compiled-channel/no-B selection. |
| Native test defaults are tag-only, strict, bounded and cached once | Root parents validate both private markers. Ordinary UID children inherit immutable FD3 defaults; validation children use separate FD4 while authenticated duplex lease remains FD3. Normal builds have no override/interceptor. Wrong adapter assumptions require harness rework, not relaxed production authority. |
| Recoverable preparation record and held-after-EOF fixture | The root0600 bootstrap record adds only isolated runner ownership; an unrecorded object is never adopted for deletion. The finite callback mode is inside strict FD4 JSON, never ordinary builds or FD3 authentication. Wrong assumptions cost bootstrap/fixture rework, not production authority. |
| Precompile/test2json execution and separated native process proof | Actual reviewed packages run; file/service faults need no redundant validation subprocess. Process-specific acceptance uses actual PID/nonce/pipe/journal. These are test execution decisions, not real service acceptance. |

## Darwin lint/ABI closure

The prior five Darwin diagnostics were not suppressed. The TCP parser helpers moved mechanically into Linux/Windows build scope. Deprecated raw Darwin syscall dispatch was replaced with five fixed libSystem imports and architecture trampolines (`fgetattrlist`, `filesec_init`, `filesec_free`, `filesec_set_property`, `fchmodx_np`) through pinned Go's supported `syscall.syscall6` linkname bridge, without CGO or a dependency. Public fd ACL removal uses FILESEC_ACL with FILESEC_REMOVE_ACL; unspecified owner/group/mode remain unchanged and the ACL query is repeated. Unsupported/query/removal errors propagate.

Primary semantic sources: [Apple getattrlist manual](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/man/man2/getattrlist.2), [filesec implementation](https://github.com/apple-oss-distributions/Libc/blob/main/gen/filesec.c), [fchmodx_np implementation](https://github.com/apple-oss-distributions/Libc/blob/main/sys/chmodx_np.c), and [filesec declarations](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/sys/fcntl.h). Apple's `acl_delete_fd_np` implementation returns ENOTSUP, so it was not used. The APIs predate macOS12. Native tests check allow/deny/inherit-only ACLs, unchanged owner/group/mode/inode, REALFSID agreement and supported local filesystem; successful compilation does not establish ABI runtime success.
