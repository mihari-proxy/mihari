# TUI 布局与可读性改进

日期：2026-09-16
状态：用户已批准，实现与验证完成
开发分支：`feat/tui-qol`（基于 `origin/dev`）

## 已确定的需求

### System 分区顺序

将 Network 移到 Ports Config 与 Daemon 之间。键盘遍历应与新的视觉顺序一致，并保持当前焦点可见。

### Connections 速率紧凑显示

用户选择紧凑缩写，优先节省 Traffic 宽度，给 Chain 更多空间。例如 `↑52.8K ↓7.3K`。

这项选择调整了 `2026-08-13-conns-traffic-fixed-width-design.md` 中不采用紧凑格式的决定；原设计防止速率数字被截断、保持列对齐的目标仍然适用。

表头说明速率单位，上传与下载保留方向标识与固定槽宽；帮助说明缩写的单位进制，并验证单位切换、大数值、零速率与窄窗口。

### Connections 代理链优先级

用户选择同时增加 Chain 的宽度，并提高窄窗口下的保留优先级：相比 Source、Destination、Rule，优先保留 Chain。

### Web GUI 响应式双卡片

用户选择顶部精简状态摘要，下方展示 zashboard 与 MetaCubeXD 两张面板卡片；宽窗口并排、窄窗口纵向排列，突出安装状态、版本和操作入口。

用户选择主操作加管理菜单：已安装面板突出 Open，未安装面板突出 Install；其余操作收进 Manage 菜单，并保留现有快捷键。

用户要求强制刷新提示必须醒目保留：在主页面顶部摘要之后、面板卡片之前使用黄色醒目提示条，突出 Ctrl+Shift+R，窄窗口自动换行，完整展示以下原文：

> If the Web GUI is blank or query parameters are missing, hard-refresh with Ctrl+Shift+R.

Gateway safeguards 移入帮助；强制刷新提示不能随之隐藏。

### Rules 详情弹窗

用户明确要求使用弹窗展示规则的具体内容，替换表格下方的小详情框。

用户确认弹窗展示当前规则的完整匹配内容（Payload）、类型、目标和匹配顺序；不进一步读取 RuleSet 内部条目。

采用居中弹窗，按终端尺寸限制宽高；长内容换行并在弹窗内滚动。关闭后保留表格原有选中行和滚动位置。

## 已批准方案

### Connections

- 紧凑速率仍采用现有 1024 进制，并通过表头/帮助说明缩写含义；不改变连接详情里的完整速率。
- Traffic 使用固定宽度的上下行槽，保留颜色与方向，不随刷新改变列宽。
- Host 保持基础识别列，Traffic 与 Chain 优先保留；Chain 获得更多剩余宽度。
- 长 Chain 延续当前末尾省略方式，完整链可在连接详情查看。

### Web GUI

- 摘要突出地址、默认面板和浏览器会话数；无默认面板不表述为网关停止。
- 卡片突出名称、默认标记、安装状态与版本；未知最新版本明确显示 Unknown，不暗示已检查更新。
- Enter 激活焦点操作；卡片按视觉顺序导航，Manage 展示设置默认、更新、重装、回滚、卸载等适用操作。
- Tab/Shift+Tab 在可操作项之间移动；原有面板选择与操作快捷键继续可用，页脚按焦点给出提示。
- 延续现有重装、回滚、卸载确认流程；无可用回滚版本时明确禁用对应项。
- 高度不足时确保焦点操作可见；所有文字保留在页面宽度内。
- Safeguards 中有些字段代表架构约束，不能渲染成全部已实时探测通过。

### Rules

- Enter 打开居中详情弹窗，内容按类型、匹配顺序、完整 Payload、目标分组显示。
- 长 Payload 换行；超出可用高度时支持上下键与 PgUp/PgDn 滚动，关闭提示固定可见。
- Enter/Esc 关闭并恢复原表格状态；打开期间方向键只影响详情。
- Providers 标签下已有详情使用同样的弹窗布局，字段保持现有含义。
