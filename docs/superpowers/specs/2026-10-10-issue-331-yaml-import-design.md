# Issue #331：本地 YAML 来源与创建时文件引用确认

状态：用户已确认设计，已实现；验证与审查结果见功能 PR。

Issue：https://github.com/mihari-proxy/mihari/issues/331

开发基线：origin/dev，49918e6；分支：feat/331-yaml-import。

本文描述最终方案。准备文档保留调查与访谈记录，范围冲突以本文及用户后续指令为准。

## 1. 来源与缓存

订阅条目使用同一个来源定位字段：现有 url 保存 HTTP/HTTPS URL 或规范的 file URI，不增加冗余持久化来源类型与文件路径字段。类型由 URI scheme 推导，已存在条目禁止跨类型转换；daemon 同样校验，不能只靠 TUI 锁定。

daemon 按自身操作系统权限读取本地普通文件，允许任意路径，不限制为调用者可读目录。接受符号链接，每次刷新解析当前实际目标，核对实际打开对象为普通文件并执行有界读取。权限不足、文件缺失、非普通文件及读取失败经原有错误分类和诊断返回。

本地来源缓存原始主 YAML 字节；Mihari 设置仅作用于生成运行配置，不修改源 YAML 或主缓存。本地源路径支持手动更新、定时刷新及关闭自动刷新，不新增 Mihari 主 YAML watcher；调度不要求客户端保持运行。

主缓存另在 catalog 中记录可选 cache-base-dir：该次成功读取主 YAML 的实际目标父目录。目录与缓存内容共同提交和回滚，不改变现有 cache/<id>.yaml 的文件布局。远程条目不写此字段。

生成本地缓存配置时，以缓存关联目录解析相对输入文件引用，并仅在运行配置中改写为绝对路径；绝对引用保持指向原文件。符号链接改变或来源路径编辑后，旧缓存仍使用旧基准，直到刷新成功。远程来源没有本地源目录，引用保持 mihomo 原生路径语义。

修改同类型来源保存新定位符，保留旧缓存和运行配置并标记来源与缓存不一致；不立即 reload。后续手动或自动刷新成功才替换内容。HTTP validators 不用于本地读取。

## 2. 文件引用与核心职责

允许主 YAML 包含本地文件引用。Mihari 不复制引用文件，不构造多文件资源缓存事务；引用文件和 URL provider 由 mihomo 原生处理。HTTP provider 的 path 是下载缓存位置，不是外部输入文件引用，不触发该类风险确认。

核心校验与运行均落实允许任意引用路径的决定：调整现有受控执行环境中的安全路径检查设置，而不是维护来源允许目录或更改 core HomeDir。不得关闭核心身份验证、扩大 controller 暴露、改变核心信任或执行安装边界。实际核心能力需核验；不支持该设置时明确失败，不宣称已实现任意路径访问。

引用检测与相对路径改写按核心字段语义处理文件 provider、证书/私钥等输入文件；区分 inline 内容、下载缓存路径、输出路径和一般字符串，不按任意 path 键扫描。实施前核对项目使用的核心字段与上游读取语义，用具体 fixtures 验证识别和改写；不重新引入完整 YAML 白名单或限制无关原生字段。

Mihari 不修改引用文件，但不保证 mihomo 所有原生文件操作只读。原生支持 watcher 的 file provider 继续监听；这与主 YAML 的刷新开关独立。主 YAML 回滚不恢复外部文件，主缓存存在也不保证完整依赖集离线可用。

## 3. 创建与确认

本地和远程新 sub 统一顺序：取得主 YAML → 解析及候选配置校验 → 如有外部文件引用则取得确认 → 创建提交。

获取或校验失败不留下条目；这是对原有远程先注册、首次获取失败仍保存条目的明确行为调整。用户拒绝文件引用确认也不创建条目。

文件引用后果仅在创建新 sub 时确认。本地与远程来源均适用，后续来源编辑、刷新、切换、启动不重复确认，包括后续刷新新出现文件引用的情况。

确认提示列出识别到的引用位置与路径值（本地来源显示解析后的路径；远程来源保持 mihomo 原生路径语义），并说明：

- Mihari 只缓存主 YAML，不备份引用文件。
- mihomo 原生监听可能使引用文件修改直接影响运行，不受主 YAML 刷新开关控制。
- 文件移动、删除、权限变化可能影响校验、运行或重启；实际访问使用 daemon/核心的权限。
- 主 YAML 回滚不能恢复引用文件；部分 mihomo 原生操作可能写入引用文件。

校验后的第一次未授权请求不持久化；TUI/交互 CLI 确认后重新读取并校验，再以新 operation ID 和授权参数提交。确认一般后果，不承诺两次请求间源内容被锁定。校验和提交之间继续复查 revision/对象身份，IO 与校验在提交锁外。

## 4. CLI 与协议增量

保留远程 sub add NAME URL；本地提供 sub add NAME --file PATH，同类型来源编辑提供 sub set ID --file PATH。URL 与文件参数互斥，路径经 platform 平台适配转换为规范 file URI。

file URI 转换覆盖 POSIX 与 Windows 盘符形式，正确处理中文、空格、百分号和 URI 转义。遵守先前绝对路径来源范围，不隐式按 daemon cwd 解释相对输入。URI 不直接传给 os.Open，也不通过 HTTP 下载器获取 file 内容。

SubscriptionAddRequest 增加可选 allow_file_references 布尔字段，对应 CLI --allow-file-references。存在文件引用但无授权时采用现有 invalid_argument，并提供 details.confirmation_required=file_references 标记与可展示说明；CLI 明确提示提供 --allow-file-references。无文件引用时不增加确认。

TUI 仅在错误码与确认标记同时匹配时打开确认；同意后使用新 operation ID，避免既有 doOperation 缓存重放第一次拒绝。非交互/JSON 不询问，缺少 flag 则退出既有参数错误码 2；交互 CLI/TUI 默认取消。

普通列表可以增加可选 source_type=file（远程省略视为 URL），仅提供类型，不增加完整来源路径或 URL 暴露。来源详情沿用显式认证 URL reveal 响应，返回包含 file URI 的来源定位符。该类型是派生展示字段，不是重复持久化字段。

原有 /v1 envelope、schema、错误码及退出码保持；文档说明远程创建失败语义的已批准变化。

## 5. TUI 表单

Subscriptions 添加表单与 Setup 首次订阅表单同时提供来源 toggle，默认 URL。沿用现有 cycle 视觉和交互，例如 Source ‹ URL › / ‹ Local file ›，左右/Space 切换；不将已有下载代理 Mode 改成来源含义。

切换时清空来源输入，不保留 URL/路径各自草稿。名称等共用字段保持；文件模式显示 YAML 路径并隐藏 HTTP 下载代理设置，URL 模式保持现有字段。Setup 保留自身已有字段范围，不顺便增加其原本没有的代理/刷新配置。

布局、输入框、placeholder、聚焦反色、圆角边框、滚动、保存按钮及运行反馈与现有添加订阅页面一致。既有表单字段下标需改为明确字段身份或统一映射，避免插入 Source 后焦点及动作错位；不做无关 UI 重构。

编辑已有条目时显示固定来源类型，不允许 toggle 转换类型，同类型定位字段可编辑。来源 reveal 尚未完成或失败时不猜测类型，也不开放转换。后端执行同样的类型约束。

普通表格明确区分本地/远程；本地不展示远程流量配额或 HTTP 下载代理模式，自动刷新开关及间隔保持可用。

## 6. 错误、回滚与兼容

手动失败在 TUI 显示概要，F2 提供原始路径和原因；定时失败记录条目状态与诊断，客户端重新连接后仍可看到。实际失败由 owner 记录一次，预期确认拒绝使用既有预期参数拒绝分类。

已存在条目刷新失败保留最后有效主缓存与运行配置。创建提交、catalog/cache 元数据、活动配置应用继续遵循准备、版本复查、原子写入和失败补偿；不能以复制源文件代替事务，也不保证外部文件回滚。

远程记录省略新增缓存目录字段，保持已有格式。旧版本不支持 file URI，且严格解码会拒绝新增目录字段；降级前须移除本地条目或恢复兼容备份。文档、CLI 帮助与 TUI 说明同步更新，不修改 CHANGELOG。

本地文件操作沿用已批准的任意绝对路径与 UNC 支持，传递取消并限制内容大小。文件系统解析、元数据查询及打开可能阻塞在 OS 的同步系统调用中（如不可达的网络共享）；执行预算和取消不保证立即中断该类调用，不通过无所有者 goroutine 隐藏阻塞。

## 7. 实施与验证

按 Red–Green–Refactor 分阶段完成来源解析/有界读取、来源校验与目录元数据、prepare-first 创建及授权、生成路径改写与核心环境、CLI/TUI 和文档。

回归覆盖：首次失败不留条目；同类型来源编辑保留旧缓存；禁止跨类型转换；符号链接版本切换与失败刷新仍使用旧目录；离线使用旧主缓存；file provider/inline/HTTP缓存路径区分；引用确认的无提交拒绝与新ID重试；定时读取失败诊断；核心校验/reload失败回滚；mode切换清空来源及两个入口一致性。

全部使用临时目录、合成内容、httptest 与 fake 核心，不运行真实系统服务或连接真实订阅。先目标包测试，再集成和全仓；按风险执行 race、vet、格式化及三平台 CGO-free 编译。本地全仓普通测试、相关功能/集成测试、vet、golangci-lint，以及 Windows/amd64、Linux/amd64、darwin/arm64 的 CGO-free 编译已通过。全仓 race 的首次 4 分钟限制在已有资源恢复矩阵超时，按 CI 的 30 分钟上限重跑已通过；CI/bot review 结果记录在功能 PR #337。
