## 已明确的目标

- System 页的 Logging 区域选中 Level 后，首次 Enter 进入右侧级别编辑。
- 右侧显示 `< INFO >` 形式的箭头提示，使用左右方向键切换候选级别。
- 切换后再次 Enter 确认修改；提交期间展示 Applying 动画。
- Q1 已确认：首次 Enter 后，将左侧 Level 的选中标记移到右侧，高亮整个 `< INFO >` 值区域，不显示文本输入用的闪烁光标。
- Q2 已确认：尚未确认修改时，Esc 放弃候选值并将焦点返回 Level；↑/↓、Tab 暂不移动焦点。
- Q3 已确认：再次 Enter 提交后，右侧显示旋转动画与 Applying…，暂时锁定编辑；成功后焦点返回 Level 并显示新值，失败则保留候选值并显示错误以便重试。候选值与原值相同时直接退出编辑，不发送修改。
- Q4 已确认：保留 DEBUG → INFO → WARN → ERROR 的左右循环；当前为 SILENT 时进入编辑显示 `< SILENT >`，首次右键到 DEBUG，首次左键到 ERROR，未切换就 Enter 则退出。SILENT 不加入可主动选择的列表。
- Q5 已确认：编辑期间外部更新不覆盖候选值；Esc 放弃候选后显示最新实际值，Enter 按现有保存流程提交候选值，冲突时显示错误。

## 既有领域约束

- System Level 是统一日志级别，不是 Logs 页显示筛选或实时流订阅阈值。
- 主动选项沿用 DEBUG、INFO、WARN、ERROR；SILENT 仅被动采纳，不新增主动选项。
- 保存继续走已有 daemon 控制平面；本次仅优化 TUI 交互。
- 关联：[统一日志级别设计](2026-09-16-unified-logging-level-design.md)。

## 完整交互流程

1. 浏览：焦点位于左侧 Level，右侧显示实际级别。
2. 编辑：Enter 将焦点移至右侧，整块高亮 `< LEVEL >`；左右键仅更改候选值，不发送修改。普通四档循环，SILENT 遵循 Q4 的入口规则。
3. 取消：Esc 放弃候选并回到 Level，显示最新实际级别；编辑期间上下和 Tab 不导航。
4. 确认：再次 Enter 提交；若无需改变当前实际级别，则直接退出。外部实际值已改变时，以 Q5 为准，仍允许提交保留的候选值。
5. 应用：右侧旋转动画与 Applying… 持续至请求结束，期间锁定编辑，防止候选改变或重复提交。
6. 结果：成功返回 Level 并显示已确认的新值；失败保留候选并显示错误，允许 Enter 重试或 Esc 放弃。revision 冲突沿用重新获取状态、不自动重放请求的处理。

## 当前实现事实

- 当前每次 Enter 直接 PATCH 下一级，没有独立候选态；普通级别首尾循环，SILENT 下按 Enter 转 DEBUG。
- 已有数值编辑以确认时最新 revision 提交；revision 冲突会重新获取状态，不自动重放请求。
- daemon 的状态同步可能在编辑期间改变实际级别及 revision；候选值与实际值需要分别表达。
- 断线或能力失效已有取消编辑与 pending 的处理，新 Level 编辑需要涵盖这些路径。
