# Logs 显示级别的跨重启保存

日期：2026-09-20

状态：Q1–Q10 已确认，Q8、Q9 按用户修订；Q10 已授权实施。2026-09-21 实现及下列验证完成，后续交付遵循[执行计划](../plans/2026-09-21-log-level-preference-implementation.md)。

工作分支：`fix/logs-debug-level`，独立 worktree，基于 `dev` 的 `f1abdd3`。

## 目标与既有语义

用户确认的问题是退出并重新打开 TUI 后，Logs 页 Level 的选择恢复默认。目标是记住已经确认的日志显示级别选择。

本设计修订 [2026-09-17 设计](2026-09-17-tui-search-history-log-filter-design.md) Q5 的“重启恢复全选，不新增持久化设置”。其余多选、草稿、非空校验、摘要及未知级别匹配语义保持既有定义。

沿用 [领域词汇表](../../../CONTEXT.md) 的“日志显示级别筛选”：它是选中级别的集合，与 System 的统一日志级别和实时日志订阅阈值无关。`DEBUG+` 是全选四个已知级别的显示摘要，不是持久化值或新增记录阈值。

## 已确认的决策

1. **Q1 保存范围**：只保存 Level 的完整勾选组合，包括不连续的组合；Wrap、搜索内容及 Pause 保持原有行为。
2. **Q2 保存时机与交互**：Level 弹窗按 Enter 后发起异步保存；保存不阻断操作，在 Level 旁播放 `Saving…` badge。Space 只修改草稿，Esc 放弃草稿，不触发保存。
3. **Q3 保存失败**：确认后立即应用新选择；保存失败不回滚当前显示，badge 改为 `Unsaved`，错误进入 F2。最初提出的重试能力已被 Q8 取消。
4. **Q4 连续修改**：页面始终立即显示最新确认的选择；后台串行保存，合并尚未提交的中间选择。旧请求完成不得覆盖新选择；只有最新选择保存成功后才能清除 `Saving…`。
5. **Q5 共享范围**：沿用同一 daemon 共享偏好的范围；同一 daemon 的多个 TUI，以及 Unix 默认系统模式的不同 UID，共享下次启动恢复的偏好。
6. **Q6 版本与布局**：TUI 和 daemon 要求同版本部署；本次不增加旧版读取新增偏好的兼容要求。扩展现有偏好文件和本地 API，并同步更新有关读取路径，不另设兼容文件。该决定不承诺降级后的旧 daemon 能读取含新字段的偏好文件。
7. **Q7 多窗口语义**：以 daemon 最后成功提交的选择作为下次启动默认值。已打开的 TUI 保留各自当前显示选择，不跟随其他窗口更新。保存 Level 只修改该偏好，不覆盖 Connections 列设置，反向亦然。
8. **Q8 不重试、不补交**：一次保存失败就结束该次尝试；不提供重试机制，不做断线后重试、重连补交、二次缓存或恢复。重新确认没有变化的选择不作为重试入口。用户修改并确认新的选择仍属于新的保存操作。Q4 仅合并本次运行中连续发生的新修改，复用当前页面选择，不新增用于失败恢复的缓存。
9. **Q9 立即退出**：退出不等待保存，不提示二次确认，不执行退出时刷盘或下次启动补交。已经提交的保留，尚未提交的允许丢失；已经到达 daemon 的请求按既有执行生命周期处理，不因客户端退出而承诺回滚或补救。

## 已核实的约束

- 当前 Logs 选择仅保存在页面内存中。既有测试明确要求切页和重连保留，创建新 TUI 时恢复全选。
- 现有 `preferences/tui.json` 只存 Connections 列选择，由 daemon 写入；同一 daemon 的所有 TUI 使用同一份偏好，Unix 默认系统模式下包括不同 UID。
- 旧版偏好读取使用严格字段校验。直接向原文件增加字段，会使旧 daemon 读取失败并导致 runtime 装配失败；Unix installer migration 也有需要一起考虑的独立严格读取路径。
- 现有偏好更新经过 Manager 的 mutation 路径；响应 revision 是全局 runtime revision，不能直接视为日志筛选自身的版本。
- TUI 不得直接写业务偏好文件；保存继续由 daemon 执行。新版本需能读取缺少日志筛选字段的既有文件，首次升级默认仍为全选。

## 已确认的收敛方案

- 首次成功读取已保存偏好时恢复选择；读取前用户已经确认了新的选择，则保留用户当前选择，迟到的读取结果不能覆盖它。重连不重新覆盖当前窗口选择，也不触发保存。
- 升级时缺少新增字段使用全选默认值；损坏或非法数据沿用既有校验和错误报告路径，不新增自动修复或恢复机制。
- 请求仅更新目标偏好，使用既有 Manager mutation 路径和原子持久化；不因 Conns 的全量对象保存而覆盖 Level。默认的新 Level 保存遵循最后成功提交生效，不引入全局 revision 冲突后的读回、重试或恢复。
- Saving 状态始终对应当前最新确认的选择；旧完成消息不得覆盖当前选择或提前结束新修改的保存状态。失败诊断遵循既有 owner 规则，避免重复记录。
- **Q10**：同版本目前是正常使用约定，建连没有构建版本相等的硬校验。本次沿用该范围，不附带新增全局版本准入机制。

## 验收场景

- 任意合法级别组合成功保存后，新 TUI 恢复精确组合；缺字段仍全选，空选择拒绝。
- 保存期间操作和切页正常；最新提交完成才结束 badge，失败保留显示并显示 Unsaved。
- 连续修改结果有序，旧结果不覆盖新值；两个 TUI 各自保持显示，新 TUI 读取最后成功提交值。
- 保存失败、重连、无改动确认和退出均不触发重试；退出不等待、不补交。
- 初始读取与用户修改竞争时保留用户选择；Level 和 Connections 列的独立保存互不覆盖。
- 持久化读取、API、Unix installer migration 对新增字段保持一致；非法输入不产生持久化副作用。
- 保持现有日志筛选匹配、草稿取消、未知级别、诊断及生命周期测试，并同步 README 中的跨重启行为说明。
