# 实例代理认证与业务数据重置设计（已批准）

## 已确认

- 认证为实例级配置，切换订阅不改变实例保存的认证凭据。
- 支持多组用户名与密码，生成 mihomo 的顶层 authentication 列表。
- 同时提供 TUI 和 CLI 配置入口。
- TUI 将 Ports Config 区域更名为 Ports & Authentication，保留端口行，增加独立代理认证弹窗入口。
- 认证用户按用户名增量合并：保留订阅中未被覆盖的用户；Mihari 配置中不存在于订阅的用户追加，同名用户覆盖密码。不采用先前建议的全量替换方案。
- 免认证名单支持三种模式，默认沿用订阅：沿用订阅保留原 skip-auth-prefixes；自定义使用 Mihari 的本机免认证开关和额外 CIDR 列表整体替换订阅名单；全部要求认证生成空免认证名单，包括本机也须认证。免认证规则不改变监听地址或局域网访问范围。
- 删除 Mihari 的同名用户覆盖项表示恢复订阅凭据，操作名称明确为“移除覆盖”；用户列表区分订阅、新增、已覆盖来源。
- 提供关闭全部代理认证选项；关闭时保留 Mihari 已编辑的凭据，以供恢复。
- TUI 密码默认遮罩并支持主动显示，编辑时留空表示不修改；CLI 支持隐藏交互输入及标准输入读取。普通列表只展示用户名、来源和覆盖状态，密码通过显式操作查看。
- 用户主动开启认证时，最终合并用户列表为空则拒绝保存并提示添加用户；未配置本功能、沿用原始订阅的实例保持现有行为。
- 保存后立即动态应用，无需用户重启内核；用户名密码通过配置热重载应用，失败恢复旧配置；内核停止时仅保存，下次启动应用。不主动断开已有连接，新连接使用更新后的认证规则。
- 显式开启认证后，订阅刷新或切换若导致最终用户列表为空，拒绝应用该候选配置并保留旧运行配置，提示认证已开启但无可用用户。
- CLI 使用 mihari proxy-auth 命令组，覆盖状态、用户、认证模式及免认证规则管理，支持隐藏密码输入与标准输入。
- 第一版不提供排除订阅用户，后续需求由 [Issue #357](https://github.com/mihari-proxy/mihari/issues/357) 跟踪。
- 认证采用三种状态，默认沿用订阅：沿用订阅不应用 Mihari 用户覆盖；启用时合并订阅与 Mihari 用户且最终至少一个用户；关闭时禁用代理认证但保留已编辑凭据。免认证模式独立配置，认证关闭时显示不生效。
- 本机免认证开关管理 IPv4/IPv6 回环范围，额外免认证 CIDR 若与回环范围重叠则拒绝保存并提示冲突，确保开关与实际行为一致。
- 提供“重置代理认证配置”：清除 Mihari 保存的用户、密码覆盖及免认证设置，恢复沿用订阅；保留订阅、端口、内核和其他设置，用户主动确认后执行。
- 提供“清除整个 Mihari 业务数据、重新初始化”选项，两类重置不能混为同一操作。已确认准确范围、入口和确认方式见下文。

## 页面结构

System 的 Ports & Authentication 区域保留 Mixed、Controller、Web 三个地址行，新增 Proxy Authentication 行，展示认证状态和用户数量并打开独立弹窗。三个端口用途不变，代理认证不替代 Web 或 Controller 认证。

弹窗包含认证模式、用户列表及免认证规则。用户列表显示用户名、来源及覆盖状态，提供新增、编辑、删除新增项及移除覆盖操作。免认证规则提供沿用订阅、自定义、全部要求认证；自定义时展示本机免认证开关与额外 CIDR 列表。

## 重置操作

### 重置代理认证配置

- 清除 Mihari 保存的代理用户、密码覆盖及免认证配置，恢复沿用订阅；不修改订阅源或缓存。
- 保留其他业务设置、订阅、端口、下载资源及日志。
- TUI 认证弹窗和 CLI 提供操作；认证配置导致启动失败时，错误提示提供恢复入口或命令。
- 用户主动确认后执行，在线应用失败恢复旧配置。

### 全量业务数据重置

用户已确认：

- 清除订阅记录及缓存、设置与代理认证、运行配置、节点选择等业务状态，以及当前用户的 TUI 偏好。
- 保留 Mihari 程序与命令入口、已安装的系统服务、已下载的 mihomo/面板/GeoIP 资源、日志和已导出的文件。
- TUI 入口位于 System → Maintenance → Reset Mihari Data，CLI 提供对应命令。
- 先预览清除范围，再进行两次确认；非交互 CLI 必须提供显式确认。
- 确认前不删除数据；重置后停止代理，TUI 返回 Setup，不自动开启系统代理或 TUN。

实现约束：

- 现有完全卸载会删除程序与服务，不可作为本操作实现直接调用。Unix service fresh 也会清除下载资源和日志，与本次范围不符。
- 不递归清空整个根目录；仅处理准确预览的受管业务对象，保留范围之外的文件。
- daemon 存活时仍由 daemon 单写入业务状态；重置场景不能扩展 CLI/TUI 直接写业务文件的权限。
- 现有不可用配置的启动恢复路径、停止 mihomo 后的资源释放、系统代理撤销及当前用户偏好归属必须在实施计划中具体核实。
- 分阶段失败不能宣称已完全重置，错误需要明确完成与未完成范围，并避免半清理状态自动启动代理。

全量重置的管理凭据处理已确认：重新生成 mihomo Controller 密钥及 Web 登录凭据，使旧 Web 登录失效；保留本地 CLI/TUI 控制凭据，以便继续连接并完成 Setup。仅重置代理认证不改变这些管理凭据。

## 本轮结论

用户已整体审核通过，并授权从 origin/dev 建立实施 worktree，按 TDD 开发、提交 PR 至 dev，处理 CI 和 bot review 至全部通过。排除订阅用户留待 Issue #357。不得通过全根删除或复用完全卸载来实现重置。

## 实施验证要求

- 按仓库 TDD 流程覆盖用户增量合并、同名覆盖与移除覆盖、认证三种状态及免认证三种模式。
- 覆盖 IPv4/IPv6 回环网段与额外 CIDR 的冲突、无用户拒绝、订阅刷新与切换的失败保留、重载失败恢复。
- 覆盖密码隐藏输入、显式查看、空密码编辑语义，以及 TUI/CLI 一致性；测试仅使用合成凭据。
- 两类重置分别验证准确清除范围和保留范围，包含服务/程序/下载资源/日志/导出/本地控制凭据；确认 Web 及 Controller 凭据更新。
- 验证预览和确认前无删除、取消、部分失败的错误汇报与启动隔离，以及重置后的 Setup 状态。
- 复用既有认证本地协议及统一 mutation 路径，不向 Web gateway 暴露凭据或诊断，不访问真实用户配置，不执行真实服务安装卸载或真实业务数据清除。

## 实现依据

- 已查 mihomo 官方 Meta 分支 hub/route/configs.go：PATCH /configs 支持 skip-auth-prefixes，但 schema 无 authentication；PUT /configs 解析并 ApplyConfig，可用于不重启进程的配置热重载。具体受支持核心版本及落地事务仍需验证。

全量重置停止代理和 Web gateway，保留认证本地 IPC；返回 Setup 并明确提示重启 daemon，以按新端口与管理凭据重新装配客户端。重启后保持 Setup 启动屏障，完成 Setup 才允许内核启动。
