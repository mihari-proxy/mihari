## 代码核查发现

以下是当前实现事实，不以历史设计文档代替代码行为：

- `internal/tui/pages/setup/model.go` 将加载失败、步骤失败和完成失败改成三类固定短句，仅 revision conflict 有独立反馈。
- 页面使用固定宽度 52 的输入框，不按收到的终端尺寸安排内容；等待状态仅为静态 `Loading…`。
- Core、订阅、GeoIP 各步骤分别执行 daemon mutation；Review 才更新端口并标记 onboarding 完成。返回不会回滚先前步骤。
- 添加订阅先持久化注册，再同步首次刷新。刷新失败时 API 仍返回注册成功，并在订阅状态保留错误；页面目前未识别这一部分成功状态。
- 返回订阅步骤再次提交会创建新 ID；重新加载也未读取已有订阅列表。
- 页面 loading 分支吞掉 Esc；没有当前步骤独立的取消与结果确认模型。
- 页面通过裸 bind 探测占用，无法辨认 Mihari 自己的监听。端口配置在 Review 才保存，启动端点依赖 daemon 重启后重新装配。
- 多数 Core/订阅失败已有安全 APIError；部分 GeoIP 普通 error 会在控制层变成 `internal error`，只改页面文案无法解决。

完整启动入口会把端口预检失败转入 `runDegradedDaemon`：IPC 和 degraded status 仍可连接，但 Runtime=nil，既不通告 SetupRequired，也不支持 onboarding GET/PATCH。因此问题是降级控制面缺少 setup 恢复能力，不是整个 daemon 进程必然退出。

## 页面与导航

保持五步概念：端口、核心、订阅、GeoIP、汇总。已有订阅时第三步展示只读概览，按 Enter 继续；正向和返回导航均不跳过该步骤。

严格复用现有 `internal/tui/ui` 的 Theme、语义色及共享组件，包括 Accent、Success、Warning、Danger、Info、Muted、边框、焦点和按钮状态。端口状态沿用既有 `StatusDot` / `ToneStyle` 设计。不得为 setup 新设色板、硬编码独立颜色、增加主题配置或改动全局主题默认值；已有主题配置和样式规则继续适用。

本次美化集中在布局、间距、对齐、信息层次和反馈完整性。内容按终端宽高排列；窄屏使用紧凑布局，长内容滚动，操作提示保持可见。低于可操作尺寸时显示明确的调整窗口提示，避免裁掉错误和按钮。界面示意的符号、边框和选中状态也以现有 TUI 组件规则为准。

## 步骤结果与恢复

每步明确区分未处理、执行中、已完成、已复用、已跳过、失败、取消收尾中和结果待确认。状态转换由页面 Update 所有，异步工作只返回值型消息；不在命令闭包中直接修改页面字段。

每次执行保留独立 ID、开始时间和请求输入快照。迟到结果通过 generation/执行身份拒绝；切换步骤、取消、重连不能让旧结果覆盖新输入。只有实际等待时调度动态指示和耗时更新。

### 核心和 GeoIP

- 读取 daemon 提供的本地状态，已就绪资源可复用。
- 状态区沿用现有主题，标签对齐；Core 分开展示本地可用性、版本、通道和运行状态，GeoIP 分 Country/ASN 展示可用性和最近更新时间。没有时间不猜测，读取失败不沿用旧的已就绪状态。
- 核心安装必须成功，安装/复用结果与 daemon 运行健康分开显示；本地核心可用不等于异步 supervisor 已健康运行。一般运行故障不反复触发 setup，缺失/不可用核心才属于必需配置恢复。
- GeoIP 明确提供跳过；跳过或不完整状态在汇总保留。
- 探测失败显示未知与可操作提示，不把未知描绘为不存在或就绪。

### 订阅

- 读取已有订阅列表；有已有项时展示总数、缓存就绪/需关注数量、各项启用状态与下载状态、当前使用项，隐藏添加表单，并提示到 Subscriptions 页面继续添加或管理。
- 没有已有项时，可添加或明确跳过；跳过无需先清空表单。
- 新增后首次刷新失败显示“已保存，首次拉取失败”，保留新订阅 ID。重试调用刷新该 ID，不再次添加。
- 同一会话返回，以及退出后重新进入，都先识别已保存状态，避免向导导航引发重复添加。
- 不将同名自动视为同一 URL，不向 TUI 回传原订阅 URL 来做去重。
- 已有但未就绪的订阅在概览给出警告，按 Enter 仍直接继续，不隐式刷新；仅本次添加未完成首次下载的项保留原地重试。返回概览不重复添加，隐藏表单不接收键盘或粘贴输入。

### 取消与退出

执行中 Esc 打开确认；确认后进入收尾状态，屏蔽重复提交。取消不能承诺回滚已经进入提交阶段的工作。

必须区分“客户端结束等待”和“daemon 已结束该次执行”。当前 operation cache 为内存缓存，已完成项可被淘汰，daemon 重启也会丢失；不能为了观察结果而重放 mutation，因为无法确认缓存仍存在时，重放可能重新执行。

按已确认的 Q11，增加向后兼容的只读 `GET /v1/operations/{operation_id}`，由 daemon 记录受支持操作的整个请求执行生命周期（订阅新增必须覆盖注册和首次刷新整体）。最小响应含既有 schema、operation_id 和 `running` / `finished` / `unknown` 状态；`finished` 只表示执行已结束，不表示业务全部成功。随后仍需读取领域状态判断部分成功。

查询通过现有认证 IPC，不触发、重放或取消 mutation，不返回请求正文或内部 cause。记录只在当前 daemon 内有界保留，不新增持久化格式；daemon 重启、记录淘汰或从未观察到请求都返回 unknown，不能据此断言未执行。新增能力标识供客户端协商；连接旧 daemon、查询不受支持或返回 unknown 时显示“结果待确认”，提供只读重新检查和退出，不盲目重交任务。只有执行已确认收尾后，才核对对应领域状态并开放下一次提交。

取消后采用独立、有界的观察 context 查询收尾状态；查询必须随页面/TUI 生命周期停止，不能继续使用已取消的执行 context。查询超时、断连或 unknown 时保留“结果待确认”分支，不承诺已经收尾。不凭一次领域状态读取宣称任务已停止，不盲目重新提交非幂等操作。

记录追踪完整执行 owner，而不是提前退出的重复请求 waiter。记录耗尽时不能驱逐正在跟踪的执行并伪报 finished；查不到时保守返回 unknown。同一 ID 存在无法唯一关联的执行时也不得把其中一个完成当作全部完成。查询不会修改既有 mutation 缓存与幂等语义。

退出前说明保留了哪些资源、哪些步骤未完成。未提交输入只在当前会话保留，不新增存储敏感表单内容的持久化格式。重进根据 daemon 实际业务状态恢复。

## 错误反馈与安全边界

- 摘要组合当前动作、既有安全错误码/消息和有依据的建议。
- 详情可含错误码、当前操作 ID、经过明确白名单选择的安全字段；不直接序列化任意 Details。
- 内部 cause 继续只用于受控诊断日志。禁止把任意 `err.Error()`、完整 URL、凭据、secret、配置正文拼入页面或剪贴板。
- GeoIP 错误应在拥有该操作语义的后端边界生成安全分类，覆盖网络、HTTP 状态、数据校验、文件提交等已有事实。
- 未知错误明确说明无法确认原因，并提供操作 ID/日志定位建议；不臆测 DNS、代理或权限原因。
- 持久化已成功但后续同步/首次刷新失败按部分成功显示，不以重做整个步骤处理。
- 新协议字段、端点或错误码若确有必要，先在本设计明确具体合同并取得确认；不借错误详情扩大原始诊断数据的公开范围。

## 端口、启动与重启

目标：本实例监听不误报为外部冲突；外部冲突可引导修正；实际生效的端点与页面显示一致；重启重连后继续向导并复用成果。

- 复用现有 daemon 启动回退、System 端口 owner 判断和服务生命周期能力。
- 仅精确识别为托管端口冲突的启动失败可建立内部受限恢复态，通告既有 onboarding 能力并支持既有 GET/PATCH onboarding；其余业务 mutation 拒绝。配置损坏、权限失败、未完成安装事务等不转成可写恢复态。
- 恢复态仍由 daemon/Manager 管理设置校验与原子持久化，不允许客户端直接改配置文件。内部通过受限 Manager mode 或最小服务适配接入现有控制层，避免将完整正常 runtime 的业务能力开放给恢复态。
- 端口检查必须区分本实例、外部占用、可用、未知；状态不确定时不自动覆盖端口。
- 复用 System 的 `ListenFree`、`LookupTCPOccupant` 和 PID owner 分类；Web 对应 daemon PID，Mixed/Controller 对应 core PID。不得凭进程名认定本实例。macOS 或权限限制导致 PID 无法确认时显示未知，不误标外部占用，也不把未知当作已经确认可用。
- 用户在端口步骤确认修改后立即通过 PATCH onboarding 保存（Complete=nil），随后处理必要重启；最终 Review 才标记完成。这样后续步骤使用重连后确认的实际端点。确认与退出提示需明确：端口也是本步骤已保存的成果。
- 重启期间明确显示状态，重连后重新读取 revision、端口和各资源状态。
- 自动重启仅复用既有本地服务适配器：服务明确 running、当前进程已提权且能确认服务对应当前连接的 daemon 时才执行。服务状态 stopped 但 IPC 在线不代表可安全启动服务，可能已有 foreground daemon 占有 IPC。
- 无权限、未安装服务、服务身份不确定或 foreground daemon 时，明确端口已保存并给出针对当前运行方式的重启提示；TUI可等待重连，也可退出后重新进入。不新增进程启动/强杀机制或 daemon restart API，不自动提权。
- CLI/TUI 不直接写 daemon 业务文件；认证 IPC、单写入者、既有配置校验与原子提交约束保持适用。

TUI 重连或重新进入时，根据 daemon 的实际配置和运行状态推导需要处理的页面，不固定回到端口步骤，不持久化页面位置。端口无效/确认外部冲突进入端口页，已保存未生效进入重启等待，核心缺失或不可用进入核心页。必需的端口和核心已就绪时直接进入主界面，可选订阅或 GeoIP 缺失不触发自动恢复向导。首次引导仍可展示可选步骤；现有 Complete 仅表示首次引导结束，不是配置完整性的唯一依据。短暂断连、启动中或读取失败显示等待/未知，不误判成未配置。每步只保存确认后的有效配置，未确认输入不落盘；最终汇总仅结束引导。
