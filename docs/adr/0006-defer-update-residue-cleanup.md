# 更新完成与残留清理分开

Issue #282 访谈 Q1–Q5 已确认：Mihari/mihomo 的已退役二进制和已完成更新事务残留统一留到后续启动尝试清理。Windows 旧映像可能仍被进程占用，不能把删除失败解释为更新失败，也不能为清理文件强制结束进程。daemon 在取得运行所有权后清理核心文件，daemon/TUI 通过 app 用例清理当前 Mihari 程序旁残留；普通 CLI 查询和安装验证子进程不清理。失败保留文件并以 WARN 进入 F2，下次启动重试。进程生命周期缺陷另行处理。

用户同意增加独立的内部待清理记录，允许同一运行期间连续更新核心。核心终态 journal 经身份核验后保存到该事务目录的 `pending-cleanup.json`，随后释放 active journal 位置；旧二进制、候选、恢复副本与 marker 此时不删除。该记录复用严格的核心 journal 内容，路径角色区分清理职责，不复用已有中断恢复记录。旧版本不会处理新增记录；配置格式、CLI、控制 API 均不改变。启动清理通过既有受限 store 和对象身份检查执行，非终态、损坏记录和不明对象保留。成功安装仍需保留的安装证明、迁移保留树、用户备份和下载缓存不属于清理对象。
