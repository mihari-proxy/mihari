# 实例配置覆写先应用 YAML 片段，再应用表单

配置覆写页提供 Authentication、DNS Override 和有序 YAML 片段；Settings 中的 Authentication 与覆写页共享同一份认证配置和编辑行为。覆写属于整个实例，刷新或切换订阅、重启后，均以当前订阅为基础重新生成运行配置。

生成时按列表顺序应用启用的片段，再应用表单中的显式选择，最后应用 Mihari 托管设置。表单选择「继承」时沿用片段处理后的结果。这样用户通过任一认证入口明确关闭认证后，片段中的凭据也无法重新开启认证。

片段的 YAML 原文决定覆写行为。普通键逐键递归合并映射，列表与标量整体替换。例如，`dns: {enable: true}` 保留已有的 `dns.nameserver`，而 `dns!: {enable: true}` 替换整个 DNS 段。

上传片段支持字段级操作符。`key!` 整体替换当前键的值，`+key` 向列表开头插入，`key+` 向列表末尾追加，`key-` 表达移除。操作作用于该键所在的层级。

同一片段按 YAML 原文的书写顺序执行操作，每一步读取上一步的结果。例如，对列表 `[A, B]` 先执行 `key-: [B]` 再执行 `+key: [B]`，得到 `[B, A]`。

在递归合并的片段中，`<key>` 表示完整的字面键名，操作符写在尖括号外。例如，`"<+.corp.example>": [A]` 给域名策略 `+.corp.example` 设置解析器，`"<+.corp.example>+": [B]` 向同一策略追加 B。已有映射与首次创建的映射使用相同的键名解析规则。普通订阅继续使用 mihomo 原生域名写法。

| 片段写法 | 对生成配置的影响 |
| --- | --- |
| `key-: [A, B]` | 按值删除列表内所有与 A 或 B 完全相等的元素，其余元素保留原顺序。即使全部匹配，键也保留为空列表。 |
| `key-: []` | 要删除的元素为零个，原列表保持原样。 |
| `key!: []` | 将该字段显式设为空列表，保留键。 |
| `key-: null` | 从当前映射中删除整个键。 |

## 编辑、预览与保存

- Mihari 内置字段由表单提供覆盖、合并、移除操作，各字段遵循自身的业务语义。上传片段的操作和作用层级单独设计。
- YAML 片段支持 DNS、认证以外的配置项，包括 `rules`。写入始终由 Mihari 管理的键时，编辑器指出具体键并阻止保存。表单允许显式覆写的键可出现在片段内，预览标明最终生效值的来源。
- 每个片段以名称标识给用户。列表展示名称和启停状态。编辑器接受多行 YAML，保存时保留原文中的注释和排版。调整顺序后，预览仍按片段名称显示来源。
- DNS 表单首期支持八项：`enable`、`ipv6`、`enhanced-mode`、`nameserver`、`default-nameserver`、`proxy-server-nameserver`、`respect-rules`、`fallback`。每项可独立沿用已有配置。
- Authentication、DNS 各自保存整张表单。片段列表将内容、顺序和启停作为一份草稿统一校验并应用。应用失败时保留此前有效的配置，编辑器保留草稿供修正。
- 默认预览显示各层处理后的相关配置。Authentication 展示认证与免认证字段，DNS 展示完整的 `dns` 段，片段编辑器展示受本次编辑、停用、删除或重排影响的顶层项。其他部分用省略号折叠。
- 焦点在编辑区或预览区时，`Ctrl+O` 均可切换同一份草稿的相关配置与完整配置预览，并保留焦点和编辑光标位置。页脚按当前视图显示 `Ctrl+O Full preview` 或 `Ctrl+O Focused preview`。认证密码默认遮罩，`Ctrl+R` 独立切换显隐，切换预览范围时保留显隐状态。
- Settings 中的重置代理认证只重置认证表单。重置后恢复继承，已启用片段提供的认证仍然有效，并在预览中显示来源。
