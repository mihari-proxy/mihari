# mihomo HTTP 诊断保留实际报错，用户输出单独整理

Issue #204 调查显示仅记录 API 错误码不足以判定失败原因。用户选择统一完善 mihomo HTTP 错误诊断，在日志中保留原始错误文本和错误链；面向用户的 CLI/TUI/控制协议继续使用整理后的错误。最初仍适用凭据及完整订阅 URL 脱敏和原有长度上限。

2026-09-14，用户确认以本地排查所需的原文为优先：文件日志、快照及导出取消内容脱敏，保留错误自带的凭据、URL、配置片段与路径；导出页面以红色文字说明分享前自行检查。诊断文本、HTTP 失败正文和 mihomo 逻辑行统一限额为 256 KiB，超限标记截断。普通响应、状态和事件仍不承载内部 cause；仅使用已有文件日志出口，不自动创建 CLI 日志。此决定替代上段的脱敏及长度策略，具体模块范围、记录责任和验证见[完整错误日志设计](../superpowers/specs/2026-09-14-full-error-logging-design.md)。
