# 本期仅修复 setup 的无关状态冲突

首次使用时，GeoIP 初始化、核心生命周期观察与日志状态同步可能推进全局 revision，使 setup 中正常执行的操作在耗时准备后被拒绝。本期只处理 setup 路径；普通 TUI、CLI 及其他客户端的同类问题另建 Issue 跟进，避免把首次使用修复扩展成整个控制协议的重设计。

Setup 遇到无关状态变化应继续；相关输入变化但用户意图仍成立时允许有界地重新准备。用户选择“setup 应该直接全量覆盖”，并明确采用 Q8 A：本次引导管理的项目以用户提交的目标为准，可覆盖另一客户端对同一项目的并发选择，不额外确认；保留其他订阅条目、面板及引导未涉及的设置。这取代此前覆盖其他客户端选择前额外确认的规则，不表示重置实例或清空业务数据。

本期覆盖 setup 的端口保存、核心、订阅、GeoIP 和完成标记全部步骤。跳过表示保留现状，已满足目标的资源直接复用；按步骤提交，后续失败保留此前成果，失败步骤在回滚成功时保留最后有效状态及输入，重新进入引导可从已有成果继续；补偿失败或一致性无法确认时进入 degraded；订阅配置事务会阻止继续修改并停止核心，用户需查看诊断、解决原因后重启 daemon，不能保证重启必然恢复。

采用新增可选请求标识及能力声明的显式 setup 执行模式，普通客户端及既有 `if_revision` 全局含义保持不变；不通过改写全局 revision 或客户端盲重试实现。Setup 添加并启用订阅在 daemon 同一步事务内完成。相关输入变化时最多追加两次准备，复用有效下载，无关后台观察不消耗次数；取消停止重做，通信中断先确认原操作结果。

旧 daemon 缺少对应能力时，在写入前提示更新并重启 daemon，不降级为旧写入行为。Setup 优先仅在本步提交时成立，后续操作正常生效，完成引导不重新覆盖之前各步。核心步骤由 daemon 在请求接受时捕获保存的通道，具体下载制品确定后不随上游变化重选；GeoIP 两库有效可用即可复用，不强制最新。

具体协议与执行设计见 [讨论及设计文档](../superpowers/specs/2026-10-14-setup-revision-conflicts-discussion.md)，用户已确认方案并授权实现、提交及创建 PR。
