# 同名节点启动告警后按名称合并处理

用户选择每次 TUI 启动检测当前加载节点的重名情况，存在重名时弹窗说明选择来源不可保证一致，但服务可继续运行；Mihari 将同名节点作为一个展示和测速项，一次测速只选择一个实际目标。这替代此前“跳过歧义项”的处理，接受测速来源可能与内核实际出口不同的局限，以保持按名称操作的简单模型。检测由 daemon 查询内核完成，不修改配置。测速固定优先使用全局普通节点，否则按 provider 名称排序选第一个匹配项，不使用随机抽取或 map 遍历顺序。mihomo 的选择是当前组顺序中的首个同名节点，告警不能将其误述为随机算法。
